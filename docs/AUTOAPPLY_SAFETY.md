# Controles y límites de seguridad AutoApply

Intervención humana v8: sin perfiles persistentes, exportación de cookies, tokens CAPTCHA, contraseñas, capturas ni trazas. Browser propietario en proceso separado y lock por sesión; comandos sin datos personales. Al continuar se comparan los campos y los bytes del CV con versiones aprobadas y se ejecuta la barrera completa existente. El evento DOM previo a navegación bloquea un desafío reaparecido; la última comprobación de autorización ocurre al despachar. Las respuestas 3xx se inspeccionan sin seguirlas: `continue_()` del navegador por sí solo no era una barrera suficiente de redirección. Un formulario caducado requiere reconstrucción y nueva verificación; un envío incierto conserva identidad y no se reintenta. El borrado profesional solicita cierre. LinkedIn/Indeed siempre manuales; ningún sitio empresarial interactivo externo está habilitado. [Alcance y fallos conservados](AUTOAPPLY_HUMAN_INTERVENTION.md).

Preparación Recruitee 20/10: petición/archivos solo en memoria, `repr` redactado y resumen sin valores personales. HTTPS/tenant/slug/URL publicada/esquema exactos, token obligatorio futuro controlado, preguntas legales sin herencia de alias de contactos y cuestionarios externos sin navegar conservan HOLD. No hay método de POST externo ni autorización inferida por publicar un API. El esquema real y el recibo local con identidad ficticia no habilitan recepción ATS ni LIVE. Se reutiliza la barrera completa prefinal. [Alcance y pruebas](AUTOAPPLY_EXTERNAL_ADAPTER.md).

- OFF y live OFF por defecto. SQLite impide `live_enabled=1` y el motor rechaza todo envío real. No hay autorizaciones ni datos personales de ejemplo en producción.
- Política inmutable, hash, consentimiento y caducidad; cambios de perfil, motor o hechos pausan. Revisión de epoch, política, anuncio, ficha, CV, evidencia y franja justo antes del paso final. Versión de adaptador no coincidente retiene.
- Sin autoridad de IA para cambiar bloqueos. El anuncio se trata como datos no confiables. CV/carta proceden de afirmaciones aprobadas; no se alimenta ningún agente con secretos ni se siguen instrucciones del anuncio.
- Los dominios de envío son exactos y HTTPS, sin credenciales ni comodines. No existe un navegador de envío público habilitado. El inspector público usa el cliente existente con DNS/IP fijadas al conectar, robots, límites y redirects revalidados.
- Playwright offline intercepta todos los recursos, bloquea desconocidos, WebSocket, service workers y descargas; usa temporales y navegador dentro del proyecto. No se guardan credenciales, perfiles persistentes, capturas ni contraseñas. No se resuelven CAPTCHA/MFA.
- Los hechos se cifran con Windows DPAPI ligado al usuario. Los documentos se cifran en disco; el directorio privado restringe herencia ACL a usuario actual/SYSTEM. SQLite contiene hashes, IDs y metadatos; el ordenador, administrador y sesión Windows siguen siendo parte de la confianza. No es protección frente a una cuenta Windows comprometida.
- PDF/DOCX con límites de tamaño/páginas y rechazo conservador de scripts/acciones, formularios PDF, enlaces/relaciones externas y objetos DOCX embebidos. Archivos legítimos con enlaces pueden rechazarse: generar una versión simple. La revisión semántica de CV importado es humana y explícita.
- Los logs de AutoApply no contienen respuestas ni documentos, solo códigos, IDs, hashes y tipos de error. Las bibliotecas de navegador no se vuelcan con textos de excepción. Los informes profesionales legibles se descargan solo por acción expresa.
- Cuotas y reserva de identidades se guardan antes del trabajo. URL canónica, empleador/título/localidad normalizados, procedencia e IDs de requisición ayudan a detectar duplicados. El criterio conservador puede retener dos puestos distintos con igual título/empresa/localidad; nunca garantiza resolver toda equivalencia entre empresas con nombres distintos. Un posible duplicado exige revisión.
- HTTP 200, clic y ausencia de email **no confirman**. La prueba offline exige recibo estructurado, ID de oferta y página posterior. No hay lector de correo implementado ni autorizado. Las confirmaciones sintéticas jamás pasan a seguimiento real.
- Un envío incierto conserva identidad y no se vuelve a intentar. Las resoluciones manuales no certifican recepción ni liberan reservas. Solo se admite volver a preparar documentos de simulación con diario completo anterior a cualquier envío, conservando intento/identidades y comprobando de nuevo cuotas y elegibilidad. No se rellenan formularios públicos y no hay reintento LIVE disponible.
- El borrado profesional revoca permiso, elimina documentos cifrados actuales y sustituye hechos por tombstones; conserva metadatos mínimos de auditoría/duplicados. No borra copias de seguridad previas, que permanecen cifradas con DPAPI. Retención actual hasta borrado explícito; no se ha programado una purga automática.

## Pendiente antes de live

Incidencia corregida de aislamiento: las primeras pruebas fijaban el entorno de Chromium, pero el controlador Node de Playwright heredaba TEMP de Windows y podía crear allí perfiles temporales. Ahora también se fija TEMP/TMP antes de iniciar el controlador y se comprueba en regresión. No se han eliminado archivos externos; no se afirma aislamiento absoluto de aquellas primeras ejecuciones.

Permiso de automatización por ATS, DOM/formulario alojado y cambios, validación de confirmación real y conciliación, ensayo autorizado, integración fiable con seguimiento, reintentos únicamente con prueba de no envío, aceptación live separada y activación autónoma delimitada. No se debe retirar el bloqueo de release solo editando una bandera: F5/F6 requieren implementación y pruebas adicionales.
# Continuación de seguridad v6

LIVE permanece bloqueado en código y SQLite. El sondeo de DOM remoto no carga la ficha profesional y solo permite GET de la vacante, robots y recursos acotados; al detectar declaración de CAPTCHA conserva el bloqueo. La preparación con datos personales utiliza un navegador sin Internet y respuestas cumplimentadas en memoria; un CV pendiente solo se admite como revisión local explícitamente marcada y nunca autoriza envío. La recepción exige correlación con un despacho POST, posting y referencia documentada; 200 aislado no confirma. Los recibos quedan cifrados, sin API keys en las URLs registradas, y no se reintenta un estado incierto. Ensayo único ligado a versiones/caducidad, sin activación autónoma implícita. Ver `AUTOAPPLY_OPERATIONS.md` para pruebas y límites reales.

# Ampliación de controles: flujo verificable

El paquete manual conserva datos personales cifrados y solo exporta en claro mediante descarga explícita; se advierte en la UI. No se envían datos a proveedores para prepararlo. Su reutilización exige ficha/CV/formulario/IT/destino vigentes y ausencia de duplicados. Una declaración manual es `DECLARED_NO_EXTERNAL_RECEIPT`, nunca recepción confirmada. No libera identidad para reintentar.

La nueva barrera prefinal vuelve a evaluar análisis, política, CV, formulario y transporte actuales. El catálogo de condiciones no otorga capacidades al adaptador ni elimina CAPTCHA. El test TCP/HTTP propio utiliza únicamente datos ficticios y no desbloquea ensayos/activación.
